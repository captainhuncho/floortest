## Hosts
- `floortest.app` — product (everything behind the coming-soon password until launch, legal pages included).
- `ops.floortest.app` — ops only, own sign-in with two-factor every time; proxy splits hosts (`src/proxy.ts`).
- DNS at the domain's cPanel host (Zone Editor): A `216.198.79.1` + `64.29.17.1`, `www`/`ops` CNAME to Vercel. Mail records belong to Google Workspace (MX, root SPF, `google._domainkey`) and Resend (`send`, `resend._domainkey`): don't touch.

## Limits and guards
- Upload 250 MB per file, 3 tracks per send, 12 per folder; artwork 25 MB.
- Rate limits: per IP on public forms (incl. "Email me when it reopens", 5/hour), per email on email-sending forms, per user on signed-in actions (`src/lib/ratelimit.ts`, table `rate_events`). Platform cap on account emails per hour (`ACCOUNT_EMAIL_CAP`, default 300).
- Caching: Next's built files (`/_next/static`, hashed names) are cached long-term on Vercel's CDN. Signed-in pages are dynamic, so Next sends them uncached. Routes that stream files set their own `Cache-Control`: `public` only for things anyone may see (QR codes of public handles, site images, receiver covers), `private` for a signed-in person's audio, stems, artwork and downloads, and `no-store` for receipts, codes, exports and admin downloads. Never mark a response that depends on a session or a private link `public`. To clear the CDN, deploy again (new hashed names) or use Vercel → Settings → Caches → Purge CDN Cache (dashboard: the owner's).
- No framing (owner's "No clickjacking" rule, 23 Oct): every response sends `X-Frame-Options: DENY` and a CSP with `frame-ancestors 'none'` (`X-Frame-Options` from `next.config.ts` on every path; the CSP from `src/proxy.ts`, or `next.config.ts` for static files; development sends both too). Nothing is meant to be embedded, so no route opens it. Checked live on 23 Oct on production and Preview: pages, sign-in redirects, `/api/*` (200 and 401), the 404 page, static files, `/receipt/…`, `/c/…`, robots and sitemap, the ops host. Only the domain redirects `www.floortest.app` and `floortest.vercel.app` (308s answered by Vercel before the app) carry neither; a redirect can't be framed. Tests: `tests/framing-headers.test.ts` (production config) and `e2e/framing.spec.ts` (each route type).
- Content-Security-Policy (audit 27 Oct): `src/proxy.ts` sends each page and API answer its policy with a fresh nonce (`src/lib/csp.ts`): `script-src 'self' 'nonce-…' 'strict-dynamic' https://challenges.cloudflare.com`, no `'unsafe-inline'`; every other directive as before (`frame-ancestors 'none'`, `style-src 'self' 'unsafe-inline'`, storage hosts for media). Next puts the nonce on its own scripts; Turnstile, Analytics and Sentry load through them. The files the proxy skips (`/_next/`, icons, fonts, images, robots, sitemap) get the same policy without a nonce from `next.config.ts` (`PROXY_SKIPS`, kept in step with the matcher by `tests/csp.test.ts`). Development sends the same, plus `'unsafe-eval'` for React's overlays, so e2e runs under it. Cost: every page now renders per request (the root layout awaits `connection()`); the 17 pages that were built ahead of time (legal and help pages, `/forgot`, `/login/code`, `/login/code/enter`, `/login/verify`, `/sent`, the 404 page) are now served by a function instead of Vercel's CDN: locally 15-20 ms either way.
- Cross-site writes (audit 27 Oct): the proxy answers 403 to a POST, PUT, PATCH or DELETE under `/api/` that the browser marks as started on another site (`src/lib/cross-site.ts`). No route sends `Access-Control-Allow-Origin`.
- Other windows (27 Oct, live in c53b6a0): every response also sends `Cross-Origin-Opener-Policy: same-origin` (`next.config.ts`), so a page FloorTest opens, or one that opens FloorTest, can't reach its window. Google sign-in is a full-page redirect and Turnstile an iframe, so nothing relies on cross-window access.
- Cost of the nonce, measured 27 Oct: the 17 pages that were static (legal pages, trust, forgot, sign-in code pages, sent) render per request, about 3 ms more each locally; on the live site a cached static page answered in 143 ms (p50) against 191 ms for a per-request page, so roughly 50 ms more per visit on those pages. Next's experimental SRI hashes were tried as the alternative: Next's 3 inline bootstrap scripts per page were blocked and pages never started, so the nonce is the working option.
- Encryption: HTTPS only (HSTS, a year, with subdomains); the database connection requires TLS (`ssl: "require"` in `src/lib/db/client.ts`). At rest, Neon and Cloudflare R2 encrypt stored data by default (provider setting, nothing to switch on); database backups are encrypted again with `BACKUP_KEY` (AES-256-GCM) before they leave the server.
- Every ops page/action names a permission or the build fails (`scripts/check-admin-perms.ts`).
- Every table has row-level security on, with no policies: only the app's own connection (the table owner) can read or write, any other role sees nothing. `scripts/check-rls.ts` (in `npm run check:perms`) applies every migration to an in-memory Postgres and fails if a table is missing it, so a migration that adds a table also adds `alter table <name> enable row level security;`.
- Per-person rules (migration `0097_person_rules`, 21 Oct): a second lock for work done for a signed-in person. `asPerson(personId, fn)` in `src/lib/db` runs every query inside `fn` (library code included) in its own transaction as the role `ft_person`, with `ft.person` set; the policies show only rows on desks that person may work (`ft_desk()`: their own id, or an account where they're in `account_members`), and teammates' user rows. Granted to `ft_person`: users (read; update own row), account_members (read), collections, tracks, senders, releases, events, stems, listens, track_comments, track_shortlist, held_replies. Any other table refuses it with "permission denied". `asSystem(fn)` steps out on purpose. Used today by `fileAccess` (`src/lib/file-access.ts`, when the request has a signed-in person) and `ownedTrack` / `ownedSender` (`src/lib/desk.ts`); `check-rls.ts` fails if a table granted to `ft_person` has no policy for it. Needs Postgres 16 or newer (`grant … with set true`).

## Working rules
- `npm run e2e`: Playwright end-to-end tests (`e2e/`) in a real browser against a throwaway local copy (fresh seeded data in `.e2e/`, local storage, no email/bot check/site password; port 3210). Covers sign-up with invite → send a WAV → receiver keeps → Download kept ZIP, plus batch actions, the app API, offline links and security guards. Stop other dev servers first.
- `npm run dev` / `typecheck` / `lint` (ESLint: Next.js rules; React Compiler advice as warnings) / `test` / `check:perms`; run migrations or scripts against a scratch `DATA_DIR`, never `./data` while the dev server runs.
- Deploy = merge `mobile-next` into `main` and push; confirm the production deploy is READY.
- More: `docs/CODE_STYLE.md`, `docs/API_GUIDE.md`, `docs/DATABASE.md`, `docs/services.md`, `SECURITY.md`.

**Listened is counted by the server** (Codex review, 19 Oct; `src/lib/review.ts` `recordListen`, migration `0096_listen_sessions`): the player posts `{ event: "play" }` when sound starts or resumes and `{ event: "beat" }` about every 10 s of sound heard to `POST /api/tracks/:id/listened`. Each beat is credited with the real time since the last one, at most 15 s, on the same sign-in; extra tabs share one row, and a paused tab earns nothing. No number from the browser is trusted, so a forged request can't mark a track Listened faster than real time. Test `tests/listened.test.ts`.

**Private files go through one check** (Codex review, 19 Oct; `src/lib/file-access.ts` `fileAccess(desk, action, trackId)`): playback, download, the app's audio, stems, the stems ZIP, track artwork and offline copies all ask it, deny by default. The desk comes from the sign-in (`currentUser()`, `appUser()` or an offline link's live checks); a track or stem id from the request is only looked up on that desk, and each action has its own rule (offline only for kept tracks in Prepare, stems only with the stems switch on). Share-link routes (`/api/c/...`) keep their own session checks; covers and site images are public. Test `tests/file-access.test.ts`.
