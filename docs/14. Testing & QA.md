# Testing & QA

Summary only. The source of truth is the linked doc; when they disagree, the code wins, then that doc, then this file.

## Test types
- Unit tests: `tests/*.test.ts` (Node test runner via tsx), `npm test`. Each file runs in its own process with its own
  throwaway database (`DATA_DIR` set to a temp folder at the top of the file), several files at once.
  `--test-force-exit` ends each file's process once its tests are done (1 Nov): PGlite's Postgres leaves a 10-second
  timer open, so every database file used to sit idle 10 s before exiting, most of the CI job's 8 minutes. Limit: the
  flag would also hide a timer or socket our own code leaves open, which used to show as a slow test file.
  `npm run test:leaks` runs the same tests and names any timer or connection still open at exit that isn't PGlite's
  (scripts/test-leak-probe.mjs); run it when a change adds timers or connections in `src/lib`.
- End-to-end: Playwright in `e2e/`, `npm run e2e`. It runs its own copy of the app on port 3210 and a fake virus scanner on 3211; both must be free. Two runs in different worktrees can go side by side on their own ports: `E2E_PORT=3220 E2E_SCANNER_PORT=3221 npm run e2e` (owner, 31 Oct: so Build's and the Desk's runs don't wait for each other). Never two runs in the same folder: they share `.next` and `.e2e/`. A spec that changes seeded accounts must still pass when it runs again in the same run (`--repeat-each`, or after a failure restarts the worker): `teams.spec.ts` keeps the owner's two-step secret in `.e2e/`, cancels its own leftover invite and sends a fresh reply text each go (31 Oct).
- Permission checks: `npm run check:perms`.
- Smoke: `npm run smoke`.

## Release checks
Before every push: `typecheck`, `lint` (0 errors), `test`, `check:perms`; `e2e` when sending, review, downloads, receipts or auth change. Each production release has a report in [evidence/](evidence/).

## Manual QA
Browser and device checks run on this Mac; phone builds per [02-technical.md](02-technical.md).

## Five-person pre-beta gate (before 1 November 2026)
Five controlled testers complete the sender and receiver journeys on phone and desktop before access widens. Record the build, device/browser, tester role, result and evidence in one test report; group duplicate findings; fix and re-test blockers. Include interrupted and duplicate uploads, email verification and receipts, listen/decision/reply/download, session revocation, cross-account access checks, cron/job visibility, backup verification and one deletion/retry exercise. Use test audio and isolated test data for destructive or time-based scenarios. Run sheet and record: [prebeta-run.md](prebeta-run.md).
