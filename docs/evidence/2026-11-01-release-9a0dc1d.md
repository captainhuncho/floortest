## What shipped
- Six ops emails are held 8 s in the outbox (`next_at`) before they go: resend from the email log, resend an invite,
  waitlist invite (one, and "invite the oldest"), plan request approve and decline. Undo (`undoSend`, needs `overview`,
  two-step) takes a signed token bound to the same admin, the mail ids and an expiry at the end of the hold. It cancels
  only mails still queued with no delivery attempt, and in the same transaction reverts the action: the invite is removed
  and the person is back on the waitlist; the plan request is pending again and an approve restores the old plan.
  Answers: "Not sent" or "Too late: it was sent". The admin log records "sent" or "cancelled".
- Never held: sign-in codes, password resets, receipts and other automatic or security mail (`queueMail` holds 0 by
  default; only the six ops actions call the held path).
- Worst case: if the server stops during a hold, the 10-minute mail job sends the mail on its next run, so up to about
  10 minutes late.
- Tests: hold, cancel, token tampering, another admin, expiry, Undo exactly as the hold ends (20 rounds, one outcome),
  server stop mid-hold, a requeued mail can't be undone, a failed revert leaves the mail queued and the action standing.
