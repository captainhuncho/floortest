## What shipped
- Migration `0126_receipt_token_hash`, expand only: adds `tracks.token_hash` and `tracks.token_sealed`, fills
  `token_hash` in SQL (sha256 hex, a test checks it matches `hashToken`), a unique index on the hash.
- Receipt lookups match `token_hash` (plus `OR token = ?` while plain tokens remain); links come from the sealed copy
  (AES-256-GCM, key from `APP_SECRET` with its own label, a random IV per row, the track id as AAD). Old rows are sealed
  on first read and nightly. Every receipt email passes the token as a secret, so stored copies show it hidden. The ops
  moderation queue no longer sends tokens to the browser. `SECURITY.md` updated.
