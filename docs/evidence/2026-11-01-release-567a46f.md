## What shipped
- #329 / #322 (owner's rule in Build): staff verification of a profile needs a reason and proof (an uploaded screenshot
  or PDF, or a link). Only the super admin or staff with `verification.direct` add the Verified mark at once; others
  propose it, and a different person with `verification.approve` approves (four eyes, enforced in the update itself).
  Approving an artist's own request needs a waiting request (#330's guard kept). One editable "You're verified" email.
  Proof files: uploaded to R2 by a signed, size-bound link, type found from the file's first bytes, copied to a new key;
  served only to verification staff from `/api/admin/verification-proofs/<id>` (same 404 for everyone else, denials
  logged), PDFs as downloads, images inline with nosniff and no-store; that one route has its own strict CSP
  (`default-src 'none'`, `frame-ancestors 'none'`). The staff reason stays in `verification_proposals`; the artist's
  page reads a note only for a rejection. Ops only, apart from the verified mark and email the artist sees.
- #331 (Backend): the teams e2e tests use their own owner account (`teams@floortest.test`, with Lena as member), so they
  never turn on two-step sign-in for the demo account that other tests sign in to. Test code only.
