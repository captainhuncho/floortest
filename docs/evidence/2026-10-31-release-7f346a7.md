## What shipped
- #216, a sending bug: on a receiver's link page, a late read of the file's own tags replaced the whole details object,
  wiping an artist or title the sender had already typed, so Send stopped at "One thing left: artist" and nothing was
  sent (Build reproduced it 1 in 10 with the old code). `src/lib/tags.ts` `fillFromFile` now fills only empty fields;
  `src/app/[handle]/useTrackUpload.ts` uses it; 3 unit tests in `tests/tags.test.ts`; `e2e/no-collection.spec.ts` asserts
  the typed artist survives (no timeout changed). This was the "flaky" e2e seen on 30 and 31 Oct. Follow-up (own PR,
  Build): `OwnerUpload.tsx` has a milder version of the same race.
- #218, sign-up and sign-in:
  - Sign-up is guided, one question per screen (`src/app/(auth)/signup/GuidedSignup.tsx`, steps in
    `src/lib/signup-flow.ts`, tests in `tests/signup-flow.test.ts`), with a password strength hint
    (`src/components/PasswordStrength.tsx`).
  - A successful sign-up lands on `/signup/ready` (`ReadySteps.tsx`) instead of the Floor; joining an existing desk
    still goes to the Floor. The redirect target is a fixed path, not taken from the request.
  - Same server action, same fields, same Turnstile check, same no-enumeration error. No new endpoints, dependencies,
    schema or migrations.
  - From #217: the sign-in, code, forgot-password, reset, Google and signed-out pages in a centred column with quieter
    fields, the club photo behind them (`public/auth/*.webp`); the role dropdown and the short legal row (labels
    unchanged) kept; the long site footer removed at the owner's request.
  - `docs/01-product.md` and `docs/03-app-flow.md` updated; e2e specs follow the new screens.
