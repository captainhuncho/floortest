## Why

The repository went public on 28 Oct, so the scanner's workers.dev address became readable by anyone. `GET /health` was
the one route that woke the container without the secret: calling it every few minutes kept it running and billed,
undoing the 26 Oct sleep saving. It could never let a file through unscanned.

This is the fourth production release today (#26, #35, #27, #41). It goes out under the security exception to the
one-release-a-day rule; no migration and no change to sending or review.

## What changed

- `scanner/cloudflare/routes.js`: `/health`, `/wake` and `/scan` need `SCAN_SECRET`; only `/status` (never wakes) is open.
- `src/lib/scan.ts`: `scannerHealth()` sends the secret to `/health`. Between the Worker deploy and this release, the
  detailed `/api/health` (cron secret) reported an awake scanner as "down"; uploads were unaffected. Caught by the
  CodeQL session's review of #41.
- `.github/workflows/uptime.yml`: the daily wake-up sends `SCAN_SECRET` (repository secret set by the owner, 20:09 UTC).
- `scanner/README.md`, `docs/operations.md`: curl commands with the secret.
