## Why

The first CI run on PR #39 (run 40763328183) failed on `tests/scan.test.ts:178`; a rerun on the same commit passed.
The test gives `scanStored` a 400 ms deadline against a scanner that never wakes. The last ask carries
`AbortSignal.timeout(left)`, so on a slow runner the deadline can land during that ask: the result is
`{ verdict: "unavailable", error: "TimeoutError" }` instead of the "gave up waiting" text. Both are the right verdict
(never "clean"); the test only expected one of the two messages.

Test-only: the app built and served is unchanged, so this doesn't count as a feature release under the
one-release-a-day rule. It is recorded here because it went through `main`.

## What changed

- `tests/scan.test.ts`: the timeout assertion accepts either `scanner answered 503; gave up waiting…` or `TimeoutError`,
  with a one-line comment saying why. No change under `src/`.
