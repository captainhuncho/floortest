## What shipped
- `src/lib/receipt-life.ts`: every track's final outcome is played out or upload + 90 days, whichever is first. From
  then the receipt is read-only; 90 days later it closes. While stems are asked for and none has been sent, the receipt
  stays open. The receiver's decision and the file's removal are never read, so the receipt can't reveal either.
- Read-only: the server refuses stem uploads and stop sharing; the page shows the record and the closing date.
  Closed: the page shows only "This receipt has closed" and Email me my sends; code requests answer as an unknown
  link's. Sender history (`/sent`) keeps the full record.
- Migration 0128 adds `tracks.art_attached_at`. "Already has artwork" now reads that mark, which survives a delete, so
  `/api/track-art/[ref]` no longer shows the sender, in the first hour after a send, that the receiver deleted the track.
- Docs: `05-data` (retention, receipt row) and `01-product`. Legal pages untouched.
- Follow-ups (Safety, not blocking, Backend's next PR): the hand-over cover update race, the delete art_key read-before-
  clear race, stronger hand-over and mid-flight delete tests, an e2e stop-sharing positive control, one `05-data` line.
